# Internationalization: Dutch and English (Phase 057)

Updated: 2026-09-24

## Implemented behavior

`shared/i18n.ts` is the typed NL/EN catalog used by both renderer modes.
`src/renderer/contexts/I18nContext.tsx` provides:

- a persisted `laro.locale` preference;
- Dutch or English initialization from the saved value or browser language;
- synchronized `<html lang>` metadata;
- typed translation with variable interpolation;
- locale-aware date and number formatting using stable `nl-NL` and `en-US` tags.

The production build isolates the shared catalog in an `i18n-catalog` chunk;
the existing 200 KiB JavaScript chunk budget remains release-blocking.

The language selector is reachable before authentication and from the signed-in
account menu. The scanner also exposes it in Settings. The localized operational
surface includes authentication and password recovery, primary navigation,
account actions, the legal-assistance safety notice, not-found handling, scanner
authorization, case selection, folder consent, scan review, upload, status, and
scanner settings. Auto-collection settings and the mounted case workspace shell
(overview, documents, timeline, matching, outreach, and their status/actions)
also use the shared catalog. The document-reconstruction controls, maps, Gantt
view, source actions, relationship labels, and correction-review workflow use
the same catalog and locale-aware date and number formatting.

Case content, evidence text, lawyer profiles, provider errors, and user-entered
data retain their source language. Backend legal classifications and persisted
state values remain stable identifiers; they are translated only at presentation
boundaries where a catalog entry exists.

## Staged renderer migration

The renderer still contains legacy user-facing literals outside the migrated
surfaces. `scripts/renderer-copy-audit.mjs` records that acknowledged debt in
`scripts/renderer-copy-baseline.json` and blocks any unreviewed additions or
changes in the stabilization gate. The current baseline contains 1,591
candidates across 56 files; a baseline entry is debt inventory, not evidence
that the copy is translated or approved. Baseline updates must accompany a
reviewed migration or an explicit classification of non-translatable provider,
unit, or example text.

## Verification

- `tests/backend/i18n.test.ts` checks both languages, interpolation, fallback,
  normalization, catalog completeness, and Intl language tags.
- `tests/browser/rendererAccessibility.spec.ts` changes EN to NL in the real
  authenticated shell; verifies navigation, the legal notice, case overview,
  evidence collection, document reconstruction, outreach, and settings; reloads
  to prove persistence; then changes back to EN and repeats the representative
  case/evidence path. The reconstruction path also renders and captures its map,
  list, and Gantt views and verifies the Dutch map after a persisted-locale reload.
  The test also requires HTTP 200, no renderer errors, and no failed or 4xx/5xx
  API requests.
- Renderer typechecking includes the catalog, provider, selectors, dashboard,
  authentication, and scanner consumers.
- `npm run verify:renderer-copy` enforces the acknowledged-copy baseline.

The Phase 057 locale runtime is implemented. Full renderer NL/EN migration
remains open engineering work until the acknowledged baseline reaches zero (or
each remaining value is explicitly classified as non-translatable). New
user-facing workflow text must enter the catalog; a missing optional translation
must remain visible rather than silently producing an empty control.
